Canavida · App de huéspedes

Publicar en Cloudflare, paso a paso

Unos 40 minutos, todo desde el navegador. Haga los pasos en orden: cada uno depende del anterior. Al final de cada paso hay una forma de comprobar que quedó bien.

Antes de empezar

Qué ya está hecho y qué le toca a usted

Ya está hecho: la app en 4 idiomas, el servidor que habla con Lodgify, la lógica de disponibilidad, el envío de correos y el asistente. Le toca a usted: crear las cuentas y pegar las llaves (pasos 3 a 7). Yo no puedo entrar a su Cloudflare ni a su Lodgify; esos pasos solo los puede hacer el dueño de las cuentas.

La conexión con Lodgify no usa usuario ni contraseña: Lodgify da una API key para que otros sistemas lean las reservas. Esa llave se guarda como secreto dentro de Cloudflare.

Cómo se conecta todo

Teléfono del huésped
Abre el enlace y escribe nombre y apellidos.
Cloudflare Worker
Sirve la app y guarda las llaves en secreto. Es el único que habla con Lodgify.
Lodgify API
Reservas en curso y próximas. De ahí salen fechas, villa, huéspedes y la disponibilidad de extras.
D1 (base de datos)
Caché de 10 min, memoria del asistente, traducciones y registro de solicitudes.
Workers AI
El asistente. Responde con las preguntas frecuentes del repositorio.
Resend
Envía cada solicitud a admicanavida@gmail.com.

Cómo se decide qué extras se habilitan: el Worker mira las otras reservas de la misma villa. Early check-in solo si nadie sale ese día; late check-out solo si nadie llega ese día; extender cuenta cuántas noches seguidas quedan libres después de la salida (máx. 3). El vino ($40) y el upgrade siempre se pueden solicitar. La tarifa de la extensión no se muestra en la app: la solicitud llega a admicanavida@gmail.com y el equipo responde con el precio.

Idiomas: la interfaz está escrita en español, inglés, francés y alemán. Los tours ya vienen en español e inglés; para francés y alemán, el Worker los traduce con Workers AI la primera vez y guarda la traducción en D1. El asistente contesta en el idioma elegido.

1

Descargar el proyecto

Descargue este proyecto como .zip y descomprímalo en su computadora. Debe ver los archivos de la tabla anterior en la misma carpeta.

2

Subir a GitHub (repositorio Brain1.0)

  1. Abra github.com/charliebrowncr/Brain1.0 (hoy está vacío).
  2. Clic en uploading an existing file.
  3. Arrastre todo el contenido de la carpeta (no la carpeta en sí). wrangler.toml debe quedar en la raíz.
  4. Commit changes.

Comprobar: en la página del repositorio ve wrangler.toml y worker.js en la lista principal. El archivo .assetsignore empieza con punto; si su computadora lo oculta, créelo en GitHub con Add file → Create new file y pegue su contenido.

3

Crear la base de datos D1

  1. Entre a dash.cloudflare.com (cree la cuenta si no la tiene; es gratis).
  2. Menú: Storage & Databases → D1 SQL Database. Si ya existe canavida (del repositorio Brain), úsela. Si no: Create database → nombre canavida.
  3. Copie el Database ID (código largo).
  4. Pestaña Console → pegue todo schema.sql → Execute.

Comprobar: en Tables aparecen cache, knowledge, conversaciones, traducciones y solicitudes.

4

Pegar el ID en wrangler.toml

En GitHub abra wrangler.toml → lápiz (Edit) → reemplace PEGUE-AQUI-EL-ID-DE-SU-D1 por el Database ID → Commit changes.

5

Obtener las dos llaves

Lodgify: Settings → Public API → copie la API key. (No está disponible en el plan Starter.)

Resend (envía los correos): cree una cuenta gratis en resend.com con el correo admicanavida@gmail.com. Sin dominio propio, Resend solo envía al correo dueño de la cuenta, que es justo lo que necesitamos. Luego API Keys → Create API key → cópiela.

Guarde ambas llaves en un lugar seguro. Nunca las pegue en GitHub.

6

Conectar GitHub con Cloudflare

  1. Cloudflare → Workers & Pages → Create → Import a repository.
  2. Connect GitHub → autorice → elija Brain1.0.
  3. Project name: canavida-app · Build command: vacío · Deploy command: npx wrangler deploy · Root directory: vacío.
  4. Deploy. En 1–2 minutos le da una dirección como https://canavida-app.SU-USUARIO.workers.dev.

Comprobar: abra la dirección y verá la pantalla de bienvenida. Desde ahora, cada cambio que suba a GitHub se publica solo.

7

Guardar los secretos

canavida-app → Settings → Variables and Secrets → Add, dos veces, tipo Secret:

LODGIFY_API_KEYla llave de Lodgify
RESEND_API_KEYla llave de Resend

Guarde y vuelva a desplegar (Deployments → Retry/Redeploy).

8

Probar con una reserva real

Abra, con el nombre de un huésped con reserva próxima:

https://canavida-app.SU-USUARIO.workers.dev/api/reserva?nombre=Ana&apellidos=Rojas

Ve sus datos y offersFunciona. Pruebe en la app.
{"notFound":true}La llave sirve; el nombre no coincide con Lodgify.
API key incorrectaRevise el secreto LODGIFY_API_KEY.
Error de D1Revise el paso 3 y 4.

Luego, en la app, pida un vino de prueba. Debe llegar un correo a admicanavida@gmail.com con nombre, villa, fechas, correo y teléfono del huésped (revise Spam la primera vez y márquelo como “No es spam”).

9

Compartir con los huéspedes

Ponga el enlace en el mensaje automático de confirmación de Lodgify. En el teléfono pueden usar “Agregar a pantalla de inicio” y queda como una app. Dominio propio (opcional): Settings → Domains & Routes → Add → Custom domain, por ejemplo huespedes.canavidaresort.com.

10

Enseñarle al asistente (cada semana)

D1 → canavida → Console. Ver qué preguntaron:

SELECT pregunta, respuesta FROM conversaciones ORDER BY id DESC LIMIT 50;

Agregar una respuesta correcta (se usa de inmediato):

INSERT INTO knowledge (pregunta, respuesta) VALUES ('Clave del portón', 'Se envía por WhatsApp el día de llegada.');

Para cambiar tours o respuestas largas, edite canavida-data.js en GitHub; se publica solo.

Si algo falla

Cloudflare → canavida-app → Observability → Logs muestra el error exacto. Cópielo y envíemelo. Mientras el Worker no responda, la app entra sola en Modo demo con las tres reservas de ejemplo (María Fernández, James Whitaker, Sophie Laurent).

Decisiones de seguridad

  • La app solo recibe nombre, villa, fechas, huéspedes y número de reserva. Correo, teléfono y montos nunca salen del Worker; solo viajan en el correo al equipo.
  • Buscar por nombre es cómodo pero adivinable. Si quiere más seguridad, se puede pedir también el número de reserva o los últimos 4 dígitos del teléfono.
